# Troubleshooting ทีมตามชั้นสถาปัตยกรรม (Harness / Loop / Graph)

เวลา agent ทำงานพลาด ให้ไล่จาก **อาการ → รู้ว่าพังชั้นไหน → ใครแก้** ไม่ต้องเดา
และเลิกโทษว่า "โมเดลไม่เก่ง" ทั้งที่จริงเป็นปัญหาการจัดวางระบบ (orchestration)

> ที่มา: บทวิเคราะห์ 2026-08-01 จากบทความ *"Agent Harness vs. Loop vs. Graph Engineering"*
> (Atlas ทบทวนสถาปัตยกรรม + Forge ทำ checklist + Vera ตรวจเข้าระบบ)

## 3 ชั้นคืออะไร (ภาษาง่าย)
- **Harness (ฮาร์เนส) = เครื่องจักรรอบตัวโมเดล** — context, เครื่องมือ, ที่เก็บความจำ,
  สิทธิ์การเข้าถึง และ **observability** (ความสามารถ "มองเห็น" ว่าระบบทำอะไรอยู่: cost/เวลา/อัตราสำเร็จ)
- **Loop (ลูป) = วงรอบทำงาน-ป้อนกลับ** — ทำ → ดูผล → แก้ → ทำซ้ำ จนถึงเงื่อนไข "หยุด"
- **Graph (กราฟ) = ผังงานที่เขียนตายตัว** ว่างานไหนต่องานไหน (ทีมเรา *จงใจยังไม่ทำ* — ดูล่าง)

การซ้อนกัน: **graph อยู่ใน harness → loop อยู่ใน graph**

## ตารางวินิจฉัยตามอาการ

| อาการที่เจอ | ชั้นที่พัง | ใครรับ | วิธีแก้ (ของเรา) |
|---|---|---|---|
| agent เข้าถึง tool/ข้อมูลไม่ได้ หรือ permission ติด | **Harness** | Forge/Cinder | เช็ค MCP config, permission ใน settings, context ใน CLAUDE.md |
| agent ลืมงานข้าม session / ทำซ้ำของเดิม | **Harness** | Sage/Lena | เช็ค `memory/`, MEMORY.md, diary, projects.json ว่าบันทึกครบ |
| cron ทีมหายเป็นช่วงๆ | **Harness** (ความคงทน/เครื่องออนไลน์ไม่ต่อเนื่อง) | Cinder | **[วินิจฉัยแล้ว ยังไม่ deploy]** ย้าย scheduler ไป home server — *ไม่ใช่บั๊กโค้ด* |
| รอบแรกเกือบดีแต่ยังไม่นิ่ง/พลาดบ่อย | **Loop** | Vera | ใส่ผู้ตรวจภายนอก (grader) + เกณฑ์ผ่านชัด + retry ไม่เกิน 3 รอบ |
| agent ทำต่อทั้งที่เสร็จแล้ว / หยุดก่อนพิสูจน์ | **Loop** | Vera | กำหนด "เงื่อนไขหยุด" ชัด — จบเมื่อผ่านหลักฐาน หรือหมดงบ token |
| งานหลายคนต้องรันตามลำดับที่คุม | **Graph** | Laura | routing ผ่าน Laura/หัวหน้าแผนก (ยังไม่ต้องทำกราฟจริง) |
| หา step ที่พังในงานหลายทอดไม่เจอ | **Graph + Harness** | Cinder + Vera | ต้องมี trace/log ผูกกับแต่ละ step → **จุดที่ทีมยังไม่มี** |
| workflow เปลี่ยนบ่อยจนวาดผังไม่ทัน | **อยู่เฉยๆ** | — | อย่าเพิ่งทำกราฟ ปล่อย Laura route เอง (ถูกแล้ว) |

## 3 กับดักที่ทีมต้องเลี่ยง
1. **"ลองไปเรื่อยๆ" ไม่ใช่ loop** — retry ไม่มีขอบเขต = token รั่ว (ชนกฎประหยัด token ของ Jed ตรงๆ)
   ทุก loop ต้องมีเป้า + งบ + จุดหยุด
2. **อย่าให้โมเดลเดียวเขียนแล้วตรวจเอง** — ทีมมี Vera แยกตรวจอยู่แล้ว = ถูกทาง อย่าข้าม
3. **harness ไม่ใช่ถังขยะ** — tool เยอะไม่ได้ดีกว่า ยิ่งเยอะ agent ยิ่งเลือกผิด (Vera audit นับ tool ต่อ agent)

## เมื่อไหร่ใช้ไฟล์นี้
- เวลา agent report ว่างานพลาด → เปิดตารางนี้ระบุ "ชั้น" ก่อนลงมือแก้
- Vera weekly audit: ใช้เป็นเลนส์จัดหมวดปัญหาที่เจอในสัปดาห์ (ปัญหาส่วนใหญ่ตกชั้นไหน = จุดที่ทีมควรลงทุนต่อ)
